## 2026-09-13 — repo scaffold

- Created `raincatgirl/WhisperPaw` (public, MIT).
- Added `README.md`, `ROADMAP.md`, `LICENSE`, `pyproject.toml`, `.gitignore`, GitHub Actions.
- Stubbed four entry points (`paw-read`, `paw-sound`, `paw-zoom`, `paw-watch`) so `pip install -e .` works and CLI shims exist.
- Wrote two skeleton tests, fixed one bug found by them (`__init__.py` didn't import the submodules).
- Status: package installs, CLI prints a friendly "not implemented yet" line, pytest is green on 3.11–3.13.
- Next tick: pick the easiest concrete tool to ship — leaning towards `paw-sound` (no platform deps).

## 2026-09-13 — `paw-sound` ships

- Implemented `whisperpaw.sound` end-to-end: arg parsing, event→file
  resolution, OS-aware audio backend selection (afplay → paplay → aplay →
  PowerShell SoundPlayer), CLI entry point with sensible exit codes.
- Shipped the first sound pack: `cat` — five short, soft WAV tones
  (ok / warn / fail / ready / ding) generated by a stdlib-only
  helper script `whisperpaw/_synth_sounds.py` (one-shot, not a runtime
  dep).
- Added 15 new tests in `tests/test_sound.py` covering parsing,
  resolution, exit-code semantics, monkey-patched backend, and pack
  discovery. Caught one bug while writing them: `SOUND_ROOT` originally
  pointed one level too high — fixed before the green.
- Total test count: 17 passing on the current Python.
- Behaviour: pure stdlib, no telemetry, no network. On a system with no
  audio backend, prints a clear "no backend found" message and exits 1.
- Next tick: keep the rest of the roadmap honest — likely the
  `paw-sound --pack forest` follow-up, or move on to `paw-read`.
